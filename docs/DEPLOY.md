# Deploying to Cloudflare Pages

The site is fully static (`dist/`), so there is no server to run or secure.

## Recommended: Git integration (no secrets in the repo)

1. Cloudflare dashboard → Workers & Pages → Create → Pages → Connect to Git.
2. Select `Henrryrocket/flash-cards-dev`, production branch `main`.
3. Build settings:
   - Framework preset: Astro
   - Build command: `pnpm build`
   - Build output directory: `dist`
4. Environment variable (only if the build uses the wrong Node): `NODE_VERSION=24`.
   The repo also ships `.node-version`.
5. Save and deploy. Pull requests get preview deployments automatically.

`public/_headers` is copied to `dist/_headers` and applied by Cloudflare (HSTS,
frame-ancestors, COOP, Permissions-Policy, immutable cache for `/_astro/*`).
The CSP for scripts and styles is a `<meta>` tag generated by Astro at build time.

## After the first deploy

- Scan the live URL with a header scanner (for example securityheaders.com) and
  confirm every header from `public/_headers` is present.
- Open each page with DevTools console open and confirm there are no CSP violations.
- Add a custom domain, then set `site` in `astro.config.mjs`.
- HSTS is sent with `preload`. Only submit the domain to the HSTS preload list
  once every subdomain serves HTTPS, because removal is slow.

## Vercel alternative

Import the repo, framework preset Astro, defaults are fine. Vercel does not read
`public/_headers`, so move those headers into `vercel.json` before using it.

## CI

`.github/workflows/ci.yml` runs tests, type check, build and `pnpm audit --prod`
on every push to `main` and every pull request. Dependabot opens weekly updates
for npm packages and GitHub Actions.
